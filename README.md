# Hi!story カード関連ツール群

同じカードDB（`data/cards.json`）を使う、2つの独立した静的アプリで構成されています。
サーバー処理は一切なく、GitHub Pagesでそのままホストできます。

- **index.html**（代理カードメモ ジェネレーター）：カードを検索して枚数を指定し、
  スリーブに挟む代理カードメモをA4印刷用PDFとしてブラウザ上で直接生成・ダウンロード。
- **explorer.html**（カード検索・関連カード探索）：カードを検索し、詳細情報（効果全文・
  収録商品一覧）と「カード間の参照関係マップ」（効果文中で名指しされている／されている
  カード一覧）を確認できる、代理カード作成とは独立した検索専用アプリ。

両アプリは `common.js`（データ読み込み・検索・参照関係マップのロジック）を共有しています。

## フォルダー構成

```
highsto-proxy-app/
├── .github/workflows/deploy.yml   # push時に自動でGitHub Pagesへデプロイ
├── data/cards.json                # カードDB本体（更新時はこのファイルを差し替え）
├── common.js                      # 両アプリ共通：データ読み込み・検索・参照関係マップ
├── index.html                     # 代理カードメモ ジェネレーター
├── script.js                      # ↑ 専用ロジック（canvas描画・PDF生成・印刷キュー）
├── explorer.html                  # カード検索・関連カード探索
├── explorer.js                    # ↑ 専用ロジック（詳細表示・収録商品一覧）
├── style.css                      # 両アプリ共通スタイル
└── README.md
```

## セットアップ手順（初回のみ）

1. このフォルダの中身をGitHubリポジトリのルートにpush（`main`ブランチ）。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を
   **「GitHub Actions」** に設定（これは一度だけ手動で必要です）。
3. 上記設定後は、`main`への push（`data/cards.json`の更新も含む）のたびに
   `.github/workflows/deploy.yml` が自動実行され、
   - `https://<ユーザー名>.github.io/<リポジトリ名>/index.html`（代理カード作成）
   - `https://<ユーザー名>.github.io/<リポジトリ名>/explorer.html`（カード検索）

   の両方に反映されます。

## カードDBの更新方法

`data/cards.json` を新しいデータで上書きしてpushするだけです。
ビルド工程がないため、他のファイルを触る必要はありません。参照関係マップも
次回アクセス時に自動で再構築されます。

## ローカルで試す場合

HTMLを直接ブラウザで開くと `fetch("data/cards.json")` が `file://` 制限に
引っかかって失敗することがあります。ローカルで確認する場合は簡易サーバーを
使ってください。

```bash
npx serve .
# または
python3 -m http.server 8000
```

## 代理カードの印刷レイアウト仕様（index.html）

- カードサイズ：63×88mm（一般的なトレーディングカードと同寸）
- 印刷内容は左右2mm・上下4mmずつ縮小して配置（黒枠＝実際の切り取り線、仕上がり59×80mm）
- A4用紙1枚あたり3×3＝最大9枚まで自動配置、超過分は次ページへ

## カード間の参照関係マップの仕様（explorer.html / 両アプリ共通）

効果文中の `〈...〉` 表記を解析し、2種類の参照を区別しています。

- **直接参照**：`〈織田信長〉` のように他カードの名前と完全一致するもの
- **系統参照**：`〈武田〉`〈真田〉のように苗字・キーワードの部分一致で、
  該当する複数カードすべてを対象とするもの

各カードについて「参照しているカード」「参照されているカード」の双方向を
一覧表示します。
